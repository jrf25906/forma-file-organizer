## [Unreleased]
### Added
- Developer workflow guidance for the `build-macos-apps` plugin now lives in `Docs/Development/BUILD_MACOS_APPS_PLUGIN.md`, with a Forma-specific reusable prompt and verification expectations aligned to `codex-project.toml`, `AGENTS.md`, `fastlane/`, and `Scripts/`.

### Fixed
- Bookmark-backed organize moves now use the same secure move path as undo/redo: production moves call `renameatx_np` with no-replace and no-symlink flags when supported, retry no-replace renames before copy fallback on filesystems that reject the strict flags, descriptor-walk search-only parent directories, keep security-scoped access alive through the disk operation, preserve the source on destination collisions, fail closed when the source cannot be pinned with an open descriptor, and use metadata-preserving open-FD copy through inode-verified temporary/final destinations before cross-volume source unlink.
- Test-plan hygiene: default, Unit, Performance, and UI Xcode test plans now carry explicit `selectedTests`, current Unit-plan suites are no longer orphaned from the allowlist, and `Scripts/verify_test_plan_membership.py` plus CI coverage now diff discovered test suites against plan membership.
- Trusted scope symlink hardening: `PathValidator` and `TrustedAutomationScopeBoundaryDescriptor.SourceBoundary.matches(file:)` now resolve symlinks before home/scope boundary checks, reject symlink escapes from scanned trusted scopes, and emit security logs outside Debug builds for rejected attempts.
- Security audit Tier A cleanup: `ThumbnailService` no longer writes previewed file paths to `/tmp/thumbnail_debug.log`, startup thumbnail-cache maintenance is scheduled after singleton construction with a retained task handle, `UITestFolderAccessConfiguration` now compiles argv-driven UI/perf folder-access overrides only in `DEBUG` or `UI_TESTS` builds while Release gets a false-only stub, and `Scripts/verify_security_configuration.sh` verifies Release binary env/path constraints plus the Release `UI_TESTS` compile guard.
- Destination prediction evaluator repair: `CoreMLPredictionEngine` now exposes shared label/probability extraction from Core ML feature providers, `DestinationPredictionService` trains and evaluates classifiers off the main actor with real probabilities when the model exposes them, label-only classifier output is rejected explicitly without fabricated confidence, confidence-separation failures get threshold-specific notes, training data uses bounded sampling before applying the dataset cap, and generated model versions now use a POSIX UTC formatter.
- The default right rail now follows the refined `Editorial Mission Control` treatment end to end: `Current Task` drops the redundant progress ring, keeps one pass-scoped linear progress row, uses a smaller headline count, and renders an equal-height shelf whose category counts stay locked to the active review pass instead of drifting with broader filtered analytics totals. `AutomationStatusWidget` now uses human-facing trust language (`files waiting review`, `folders on autopilot`, `folders blocked`) and removes builder-sounding helper copy, while the review floating action bar now reports blocked states like missing destinations or pending review truthfully instead of falling back to `No files ready to organize`. `Next Moves` keeps the ranked editorial feed while using a tighter semantic color system and footer CTAs that leave more room for the actual briefing text.
- The approved `v4` compressed-editorial pass now gives `Next Moves` a stronger featured-card composition: metadata and supporting metric sit in a slim top row, the title/summary regain full-width measure, the explicit `Why it matters` line stays in the body, and the CTA remains pinned in a divided footer so the recommendation reads like an editorial briefing instead of an admin tile.
- Boundary flattening follow-up: the `Current Task` category shelf now stays a compact fixed-height footer band instead of stretching into a second content area, `AutomationStatusWidget` now renders as one outer surface instead of an inset card inside a card, and `Next Moves` now uses a quieter outer wrapper so the featured recommendation remains the only strong internal boundary.
- Dashboard workspace routing now uses an explicit root-state contract: `Home` launches with the persistent sidebar plus center workspace and inspector, left-nav/global `Analytics` and `Smart Rules` use the full area to the right of the sidebar instead of a squeezed right-panel treatment, `Back to Dashboard` restores the exact prior `Home` inspector visibility/mode/width, and the toolbar inspector toggle is disabled outside `Home`. `WindowPresentationStore` now persists the preferred inspector width, and UI coverage asserts `homeWorkspace`, `analyticsWorkspace`, and `rulesWorkspace` directly.
- Batched persistence, retention, and onboarding verification:
  - `FileOrganizationCoordinator` now prefetches bulk organize/undo/redo state once, stages file-item, metadata-history, activity, and personal-memory mutations in one `ModelContext`, and performs one persistence save per batch instead of per-file saves.
  - Bulk organize/undo/redo still tolerate per-file move failures, but a final persistence failure now compensates successful disk moves and restores model state so Forma does not leave disk and SwiftData out of sync.
  - `FileMetadataFoundationService`, `PersonalMemoryService`, and `ActivityLoggingService` now expose no-save staging paths used by the batched organize/undo/redo flow.
  - `HistoryRetentionService` and `FormaConfig.retention` now prune workflow audit, trusted-scope run history, and personal-memory event history by a shared 90-day window plus default caps of 2,000 workflow runs, 100 trusted-scope runs per scope, and 10,000 personal-memory events.
  - Workflow-audit latest-run lookups, trusted-scope summaries, and personal-memory evidence scans now use bounded fetches instead of fetch-all plus in-memory filtering.
  - Downloads onboarding now re-checks actual access after the macOS folder picker succeeds; cancellation or failed verification keeps the user on `Get Started` with a visible retryable error instead of finishing onboarding early.
- Critical-path optimization follow-through:
  - `AnalyticsDashboardViewModel` now diffs persisted cluster membership before fetch/save, so a changed scan that converges to the same cluster set skips the persistence pass entirely instead of reloading and rewriting identical `ProjectCluster` rows.
  - `DashboardViewModel` / `DashboardView` now give startup scan and deferred maintenance a single owner, moving optional work off the first meaningful dashboard view and preventing duplicate launch-triggered refreshes.
  - `DashboardViewModel.handleDashboardStartup(context:autoScanOnLaunch:)` now marks the launch scan as complete only after a non-cancelled pass finishes, so a cancelled startup attempt still retries the first real scan on the next launch-owned run.
  - Inspector open paths now reuse selection-local matched-rule and workflow-preview state, while expensive simulation and metadata proof refreshes are deferred off the initial inspector reveal.
  - Rule authoring now routes writes through shared `RuleAuthoringService` delta evaluation instead of rewalking every rule/file pair for small preview/save edits.
  - Watched-folder refreshes now flow through a real delta path: the watcher emits touched roots plus updated/removed standardized paths, realtime scans debounce at `0.2s`, single-root batches below the escalation threshold scan only explicit touched files, and the dashboard merges those file-row changes without rerunning cluster/project-space refresh work.
